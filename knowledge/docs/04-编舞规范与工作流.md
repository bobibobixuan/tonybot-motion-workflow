# 04 编舞规范与工作流

## 工作流目标

本仓库把“需求 -> 编舞 JSON -> `.rob` -> 审计报告 -> 时间线可视化”固化成标准流程。

## 标准输入

编舞输入放在 `编舞/<名称>.json`，常见字段包括：

1. `name`
2. `prompt`
3. `segments`
4. `guards`
5. `metadata`

其中 `guards` 用于在主体动作前后注入保护段，适合回正、稳态起拍和稳态收尾。

## 标准输出

每个新舞蹈至少应产出：

1. `编舞/<名称>.json`
2. `动作/<名称>.rob`
3. `编舞/<名称>.report.json`
4. `编舞/<名称>.timeline.html`

## 生成策略

默认采用保守编舞策略：

1. 优先从 `动作/` 或 `动作模块/` 复用动作段。
2. 可以裁剪、重复、拼接官方动作帧。
3. 不默认手写整段全新舵机轨迹。
4. 需要自定义帧时，必须接受安全审计。

## 典型命令

初始化编舞模板：

```powershell
python dance_workflow.py init 编舞/示例舞蹈.json --name 示例舞蹈 --prompt "做一段适合展示的机器人舞蹈"
```

构建编舞产物：

```powershell
python dance_workflow.py build 编舞/159号自制舞蹈.json
```

单独执行安全审计：

```powershell
python rob_safety.py "动作/159号自制舞蹈.rob"
```
