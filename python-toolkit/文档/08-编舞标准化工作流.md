# 编舞标准化工作流

从舞蹈创意到机器人可执行 `.rob` 文件的完整 SOP。本指南桥接官方 Hiwonder SDK 与项目工具链。

## 快速概览

```
舞蹈创意 → 研究分析 → 编舞 JSON → 安全审计 → .rob 产物
                ↑                    ↑
          查动作库目录          rob_safety.py
          文档/07-动作库目录.md
```

**核心原则：** 优先复用官方动作帧，不手写舵机轨迹。所有产出必须通过安全审计（`violations=0`）。

---

## 第一步：创建编舞模板

```powershell
uv run python dance_workflow.py init 编舞/<舞蹈名>.json `
  --name "<舞蹈名>" `
  --prompt "<舞蹈需求描述，越具体越好>"
```

模板结构：
```json
{
  "name": "<舞蹈名>",
  "prompt": "<需求描述>",
  "research": {
    "query": "<需求描述>",
    "summary": [],
    "references": []
  },
  "visualization": { "title": "<舞蹈名>", "theme": "sunset" },
  "output": {
    "rob": "动作/<舞蹈名>.rob",
    "report_json": "编舞/<舞蹈名>.report.json",
    "visualization_html": "编舞/<舞蹈名>.timeline.html"
  },
  "guards": {
    "pre_segments": [],
    "post_segments": []
  },
  "segments": []
}
```

---

## 第二步：填入研究摘要

如果舞蹈有已知参考（如网络热门舞蹈），在 `research` 中填入：

```json
"research": {
  "query": "科目三舞蹈 动作拆解 节奏特点",
  "summary": [
    "核心节奏型：慢-快-快-停",
    "标志动作：左右摆臂+侧滑步",
    "情绪：潇洒、自信、带律动感"
  ],
  "references": [
    {"title": "科目三舞蹈教学", "url": "https://example.com"}
  ]
}
```

---

## 第三步：编排 segments

### 3.1 查动作库目录

打开 `文档/07-动作库目录.md`，按需查找：

- **开场/收尾** → 基础模块（301 站姿基座, 302 快速回正, 303 鞠躬）
- **移动** → 侧滑（309-311）、踏步（307-308）、转向（344-347）
- **表现力** → 拳击（317-325）、踢腿（314-316）、扭腰（312-313）
- **地板动作** → 俯卧撑（331）、仰卧起坐（332）、下蹲（329-330）
- **节奏模板** → 334-341（各热门歌曲节奏框架）

### 3.2 写 segments

每个 segment 引用一个 `.rob` 动作文件：

```json
"segments": [
  {
    "label": "开场亮相",
    "source": "303号礼貌鞠躬.rob",
    "notes": "面向观众鞠躬，建立表演感"
  },
  {
    "label": "节奏踏步",
    "source": "308号标准踏步.rob",
    "repeat": 2,
    "notes": "双次踏步建立节奏"
  },
  {
    "label": "左滑展示",
    "source": "309号左侧滑短句.rob",
    "frame_range": [0, 10],
    "notes": "取前10帧做短促左滑"
  },
  {
    "label": "出拳高潮",
    "source": "319号左右勾拳组合.rob",
    "repeat": 2,
    "notes": "重复两次左右勾拳，作为视觉高潮"
  },
  {
    "label": "收尾鞠躬",
    "source": "303号礼貌鞠躬.rob",
    "notes": "结束致意"
  }
]
```

### 3.3 添加安全 guards

所有编舞都应注入自动回正保护段：

```json
"guards": {
  "pre_segments": [
    {
      "label": "auto-reset-in",
      "source": "302号快速回正.rob",
      "notes": "开场前自动回正到稳定站姿。"
    },
    {
      "label": "auto-stand-in",
      "source": "0号立正.rob",
      "notes": "确保从标准站姿开始。"
    }
  ],
  "post_segments": [
    {
      "label": "auto-reset-out",
      "source": "302号快速回正.rob",
      "notes": "收尾自动回正。"
    },
    {
      "label": "auto-stand-out",
      "source": "0号立正.rob",
      "notes": "结束在稳定站姿。"
    }
  ]
}
```

### 3.4 关键字段说明

| 字段 | 必需 | 说明 |
|------|------|------|
| `label` | 推荐 | 段标识名，用于报告和时间线 |
| `source` | 是 | 引用 `.rob` 文件名，从 `动作/` 目录查找 |
| `repeat` | 否 | 重复次数，默认 1 |
| `frame_range` | 否 | `[start, end]` 截取帧范围 |
| `notes` | 否 | 备注，写入选段原因 |

---

## 第四步：构建和审计

```powershell
uv run python dance_workflow.py build "编舞/<舞蹈名>.json"
```

构建过程自动执行安全检查。产物：

| 文件 | 说明 |
|------|------|
| `动作/<舞蹈名>.rob` | 可部署到设备的 ACT-40 二进制动作文件 |
| `编舞/<舞蹈名>.report.json` | 安全审计报告，含帧数、时长、边界检查 |
| `编舞/<舞蹈名>.timeline.html` | 可视化时间线，可在浏览器中查看 |

如果安全审计不通过（`violations > 0`），构建会中断，需要调整 segments 后重试。

---

## 第五步：独立安全复核

```powershell
uv run python rob_safety.py "动作/<舞蹈名>.rob"
```

合格标准：`violations=0`，无 error 级别违规。

---

## 第六步：部署到设备

将 `.rob` 文件传输到 Tonybot，在 `main.py` 中通过以下方式执行：

```python
import Hiwonder
tony = Hiwonder.Tonybot()

# 通过 BLE 命令触发
# CMD|2|<动作组编号>|$

# 或在 MicroPython 中直接调用：
tony.runActionGroup(N, 0)   # 参数 N 对应 .rob 文件编号
tony.waitForStop(5000)
```

> 注意：`.rob` 文件编号需与设备端动作组编号一致。新生成的 `.rob` 文件需要放入设备的动作存储区才能被 `runActionGroup()` 调用。

## 编舞设计原则

1. **安全优先**：所有段的前后衔接必须通过包络审计，禁止跳变超出官方样本范围
2. **回正规范**：开场和收尾必须回到标准站姿（0号立正）
3. **节奏合理**：单帧时长 40-1800ms，95% 分位 800ms，避免过短或过长的停顿
4. **动作递进**：从低强度（踏步/侧滑）→ 中强度（扭腰/踢腿）→ 高强度（拳击/下蹲）→ 回正
5. **复用优先**：优先用预设模块（301-350），其次官方动作（0-104），最后才考虑手写帧（351-400）

## 与官方 SDK 的关系

| 层 | 工具 | 作用 |
|----|------|------|
| **PC 端工具链** | `dance_workflow.py` / `rob_compose.py` / `rob_safety.py` | 生成安全 `.rob` 动作文件 |
| **设备端运行时** | `Hiwonder.Tonybot` / `main.py` | 加载并执行 `.rob` 文件，驱动舵机 |

`runActionGroup(N, mode)` 中的 `N` 对应 `.rob` 文件编号。PC 端工具链确保生成的 `.rob` 文件在设备端可以安全执行。
