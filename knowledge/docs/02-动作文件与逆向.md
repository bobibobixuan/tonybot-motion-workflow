# 02 动作文件与逆向

## 已确认结论

当前可作为工程事实使用的逆向结论如下：

1. `.rob` 外层容器是 `ACT-40`。
2. 文件结构是 `16 字节文件头 + frame_count * 248 字节帧区`。
3. 明文帧前 16 个槽位是有效动作槽位，后 24 个槽位是 filler。
4. `EYPT` 使用标准 `TEA-32`，密钥在 `rob_crypto.py` 的 `ENCRYPT_ARRAY`。
5. 加密范围是 `data[16:]`，文件头本身不参与加密。
6. 官方 `EYPT` 样本必须支持“解密 -> 重加密 -> 逐字节一致”往返验证。

## 仍未完成的逆向部分

1. 每个有效槽位第 2、第 3 个 `u16` 字段的精确物理含义。
2. 帧头保留字段在设备端是否有特殊运行时用途。
3. 从零手写任意舵机轨迹时的绝对安全性证明。

## 当前工程判断

逆向现状应表述为：

1. 容器层完成。
2. 加密层完成。
3. 动作语义层部分完成。

因此仓库已经足够支持解析、解密、重加密、裁剪、拼接和受约束生成，但还不足以宣称“完全脱离原动作库自由生成任意动作”。

## 相关工具

1. `rob_reverse.py`：解析 `ACT-40` 和逐帧字段。
2. `rob_crypto.py`：`EYPT` 的独立加解密实现。
3. `rob_library.py`：批量导出动作库结构和统计。
