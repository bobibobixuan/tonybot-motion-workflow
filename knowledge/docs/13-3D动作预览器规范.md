# 13 3D 动作预览器规范

本文档定义当前 `simulator/` 网页预览器的职责边界、输入输出、页面组成和验证标准。

## 一、正式定位

正式名称：

```text
Tonybot Action Simulator
```

它的定位不是“安全仿真器”，而是：

1. 16 路舵机动作校对工具
2. `.rob` 文件逐帧姿态预览器
3. 关节映射交叉审核页面

## 二、输入

预览器接受两类输入：

1. 手动拖动 16 路滑块
2. 读取 `.rob` 文件帧序列

支持格式：

1. ACT-40 明文
2. EYPT 加密（TEA-32）

文件结构：

```text
[16 字节文件头] + [frame_count × 248 字节帧区]
```

每帧取前 16 个有效槽位作为 `pose[16]`。

## 三、权威映射来源

预览器的舵机映射必须遵循：

1. `data/servo-map.json`
2. `knowledge/docs/14-servo-layout.md`

不得在页面、JS 或文档中再维护一套互相矛盾的旧命名。

## 四、页面结构

当前页面必须保持“三栏校对结构”：

### 左栏：映射总览

至少包含：

1. 实时 Pose 数组
2. 当前舵机详情卡
3. 镜像对照列表
4. 16 路映射速查卡片

### 中栏：3D 视口

只做：

1. FK 姿态预览
2. OrbitControls 视角控制
3. 舵机标签显示/隐藏

### 右栏：交互控制

至少包含：

1. 16 路滑块
2. 预设姿态按钮
3. `.rob` 加载入口
4. 时间轴播放、逐帧和倍速

## 五、命名规则

页面必须直接展示实测中文名，例如：

1. `ID8 右肩根部旋转轴`
2. `ID7 右肩侧向轴`
3. `ID2 右踝俯仰轴`

不要把这些位置退回成模糊命名，例如：

1. `shoulder_axis_2`
2. `ankle_axis`
3. “肩部第二轴”这类没有实测语义的信息占位名

内部 `joint` 字段允许保留 `r_shoulder_pitch` 这类工程名，但界面默认优先展示中文实测名。

## 六、渲染模型

当前渲染层采用舵机驱动模型：

1. 每个 `ID` 都渲染为 `servoCase + servoHorn + childRoot`
2. 下一级肢体挂到 `childRoot`
3. `setPose()` 表达的是舵盘输出角变化
4. 腿部层级为 `1→5→4→3→2` 和 `9→13→12→11→10`
5. 手臂层级为 `8→7→6` 和 `16→15→14`

## 七、禁止输出的内容

页面中**不得**出现以下内容：

1. 平衡分
2. 质心位置
3. 支撑多边形
4. 安全通过/失败
5. “危险动作”“建议调整重心”这类安全判断语句

帧跳变提示仅允许输出：

1. 哪两帧之间发生跳变
2. 哪几个 ID 跳变
3. 各自跳变量

## 八、推荐验证流程

每次修改预览器后，至少执行：

1. `node --check simulator/js/config.js`
2. `node --check simulator/js/robot-scene.js`
3. `node --check simulator/js/simulator-app.js`
4. `Get-Content -Raw -Encoding UTF8 data/servo-map.json | ConvertFrom-Json | Out-Null`
5. 启动 `simulator/start-simulator.ps1`

页面级检查：

1. 页面能正常打开
2. 左栏 16 路速查卡片名称和右栏滑块名称一致
3. 拖动任意滑块时，中栏姿态立即变化
4. 当前舵机详情卡会跟随聚焦通道更新
5. `.rob` 文件拖拽后可逐帧播放
6. 控制台无报错

## 九、与 `rob_safety.py` 的关系

| 项目 | 动作预览器 | `rob_safety.py` |
|------|-----------|-----------------|
| 定位 | 可视化校对与预览 | 安全审计 |
| 输入 | 滑块或 `.rob` | `.rob` |
| 输出 | 姿态、时间轴、映射参考 | violations 和审计报告 |
| 平衡结论 | 不提供 | 提供 |
| 使用时机 | 编舞和映射核对阶段 | 构建和验收阶段 |

两者互补，不能互相替代。
