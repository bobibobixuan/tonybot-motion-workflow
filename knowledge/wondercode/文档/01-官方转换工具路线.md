# 官方转换工具路线

`wondercode-toolkit/` 的定位和 `python-toolkit/` 不一样。

- `python-toolkit/` 解决的是：`.rob`、`ACT-40`、`EYPT`、安全拼接、逆向工具链。
- `wondercode-toolkit/` 解决的是：**官方积木代码如何稳定落到 Python**。

这意味着这里的“正确性来源”不是逆向推断，而是：

1. 在 WonderCode / 官方积木编辑器里搭好积木。
2. 用官方提供的转换工具导出 Python。
3. 把导出结果整理成可读、可查、可复用的文档和示例。

## 为什么单独拆一套

之前如果从“反向编译”角度理解积木，容易混入两类噪声：

1. 把 GUI 上的积木语义误当成 `.rob` 动作编排语义。
2. 把官方转换器的实际 API 输出，替换成自己推测的设备端写法。

这两件事都不利于后续维护。当前策略改成：

- **以官方转换工具的 Python 输出为准**
- 先忠实记录，再在此基础上做整理和封装

## 当前确认的代码骨架

官方转换出的主程序骨架如下：

```python
import Hiwonder
import time
import Hiwonder_IIC
from Hiwonder_BLE import BLE

tonybot = Hiwonder.Tonybot()
beep = Hiwonder.Buzzer()
i2c = Hiwonder_IIC.IIC()
imu = Hiwonder_IIC.MPU()
ble = BLE(BLE.MODE_BLE_SLAVE, "Tonybot")
uart = Hiwonder.UART(9600, 2, 5)

def start_main():
    ...

Hiwonder.startMain(start_main)
```

这几个点后续应当视为当前路线的固定基线：

1. 主入口是 `Hiwonder.startMain(start_main)`。
2. 蓝牙实例来自 `Hiwonder_BLE.BLE`，不是 `Hiwonder` 命名空间里的类。
3. IMU 角速度和姿态角分别来自 `imu.read_gyro_data()` 与 `imu.read_angle()`。
4. UART 与 BLE 的“解析命令”接口风格一致，都是 `parse_uart_cmd(...)`。

## 推荐工作流

当你要补新指令时，优先按这个顺序做：

1. 先在官方积木里拼出最小样例。
2. 导出 Python。
3. 把导出代码追加到映射文档。
4. 只有在多次导出确认稳定后，再考虑封装辅助函数。

不要反过来先写“理想 API”，再倒推积木含义。这里的目标是对齐官方，不是重写官方。
